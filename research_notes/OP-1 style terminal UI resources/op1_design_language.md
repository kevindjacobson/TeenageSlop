# Visual design language of the Teenage Engineering OP-1 display UI (and OP-1 field / OP-Z / EP-133), plus open-source recreations and asset sources

Scope note: research was done 2026-10-21 via web search/fetch, GitHub API (`gh`), and two user-supplied reference screenshots saved beside these notes as `reference_op1_screens.png` and `reference_op1_screens_2.png`. All TE screen artwork, firmware SVGs, and the `opfont.svg` font are proprietary (© Teenage Engineering AB); every community project found treats them as "use your own firmware locally, never redistribute". Everything below separates *what is legally reusable as inspiration* from *what is copyable*.

---

## Key Question 1: What are the canonical OP-1 UI colours (hex)? Are there published palettes?

### Takeaway
There is no official TE-published hex palette. The best primary-ish source is a custom-firmware developer ("popcorp"/pcppcp, author of op1r) who posted the stock SVG palette read from the firmware: **Blue #4D9EFF, Green #00ED95, White #FFFFFF, Red #FF3A5D, Grey #6F7173, Lilac #DFD9FF, Pale #AEB1DC on a #000000 background, with no opacity support**. A second, independent community token set (SquareWave Studio's op1-design-kit) uses #698EFF / #00ED95 / #FFFFFF / #FF423F / #B9B9C9 / #625D77 and explicitly says these are preview tokens, not calibrated OLED values. The green (#00ED95) agrees across both sources; blue and "orange/red" differ between them. No Lospec, color-hex, Coolors, Figma Community or Dribbble palette named "OP-1" was found.

### Cited Findings
- Stock palette as read from the firmware SVGs by op1r's author, posted in the op-forums custom-firmware thread (post #1373): "Blue #4D9EFF (knob 1), Green #00ED95 (knob 2), White #FFFFFF (knob 3), Red #FF3A5D (knob 4), Grey #6F7173 (neutral lines), Lilac #DFD9FF (extra accent), Pale #AEB1DC (extra accent)". Also: "Use only the stock palette. An element takes its controlling knob's colour. For dim states, use darker versions of the same colours, since 'There's no opacity.'" — [popcorp, op-forums.com custom firmware thread #1373](https://op-forums.com/t/custom-firmware-on-the-op-1/4283/1373)
- Same post: the canvas is 320 × 160 SVG user units (`viewBox="0 0 320 160"`), "scaled to the OLED, which has two variants"; "keep content above about y 140; the lower edge is unreliable on the device"; coordinates in firmware code are Q10 fixed point ("1 px = 1024"). — [popcorp #1373](https://op-forums.com/t/custom-firmware-on-the-op-1/4283/1373)
- op1-design-kit tokens (`op1-ui/tokens/op1-ui.json`, v0.2.0, target "original-op1"): `background #000000, blue #698eff, green #00ed95, white #ffffff, orange #ff423f, secondary #b9b9c9, decorative #625d77`; `encoderOrder: blue, green, white, orange`; coordinateSpace 320×160 "logical-pixel". Provenance field: "Kit palette op1-kit-v1; consistent preview tokens, not calibrated OLED colours or a claim of exact stock values." — [squarewave-studio/op1-design-kit op1-ui.json](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/tokens/op1-ui.json)
- The kit's DESIGN.md palette table repeats those values and notes "The fourth control is called Orange here; older op1r documentation sometimes calls it Red. The kit token for that role is red-orange." — [op1-design-kit DESIGN.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/DESIGN.md)
- The OP-1 firmware takes "colors for dynamic parts from colors.svg, and characters for dynamic text from opfont.svg. Static parts of each graphic define their own colors and text in their individual SVG files." — [op1hacks/docs svg.md](https://github.com/op1hacks/docs/blob/master/svg.md)
- op1hacks' font/symbol table gives the symbol colours used in the stock font: FX/Envelope/LFO/Synth/Keyboard/Blend/EQ symbols are blue (synth side); the drum-side FX/Envelope/LFO symbols are green; Tape symbol red; Mixer symbol gray. — [op1hacks/docs README](https://github.com/op1hacks/docs)
- TE's own words on the encoder colours (OP-1 field user guide, firmware 1.7.0 REV 10, p.3): "encoders in the color palette of blue, ochre, gray and orange to keep things playful … the display is a custom made color lcd, mounted directly onto the keyboard." (Field hardware knob caps are blue/ochre/gray/orange; the on-screen colour language is still blue/green/white/orange-red.) — [OP-1 field user guide PDF](https://assets.teenage.engineering/_img/69f248938d433104c4dd1846_original.pdf)
- Same guide, p.8: "the four color coded encoders are related to the graphical interface on the display. by turning an encoder, you control the parameter with the corresponding color. an encoder can have multiple functions. using an encoder in combination with the shift key usually allows for fine tuning, and tapping an encoder usually means 'confirm', 'return to default' or access to even more extensive features." — [OP-1 field user guide PDF](https://assets.teenage.engineering/_img/69f248938d433104c4dd1846_original.pdf)
- Original OP-1 guide, layout chapter: "The four color encoders are related to the graphical interface on the display." and "A green graphical element or text hints that the green encoder will change its value or position." — [teenage.engineering/guides/op-1/original/layout](https://teenage.engineering/guides/op-1/original/layout)
- Sound On Sound review: the 320 × 160-pixel OLED "uses colour and animation meaningfully"; "colour is the natural link between on-screen objects and encoders". — [Sound On Sound OP-1 review](https://www.soundonsound.com/reviews/teenage-engineering-op1)
- Mixer colour mapping (official): track 1 blue, track 2 green, track 3 white, track 4 orange; EQ low blue, mid green, high white, EQ amount orange. — [teenage.engineering/guides/op-1/original/mixer](https://teenage.engineering/guides/op-1/original/mixer)
- Synth envelope mapping (official): Blue Attack, Green Decay, White Sustain, Orange Release; "This will be indicated by a color change in the graphical interface as soon as an encoder is turned." — [teenage.engineering/guides/op-1/original/synthesizer-mode](https://teenage.engineering/guides/op-1/original/synthesizer-mode)
- A third-party design essay (not TE) lists a "Teenage Engineering" *brand* palette: orange #ff6600, true black, true white, aluminium grey #d4d4d4, "OLED green" #00ff66 — this is the author's interpretation with no citations and is about brand/web, not the device screen. — [blakecrosley.com guide](https://blakecrosley.com/guides/design/teenage-engineering)
- WebGradients hosts a "Teenage Engineering website colour palette" (grey/near-black/red accent) sampled from the company website, not the device. — [webgradients.com](https://webgradients.com/palette/teenage-engineering-website-color-palette)
- Reference screenshot observations (user-supplied captures, `reference_op1_screens.png`, `reference_op1_screens_2.png`): pure black background; four hues only — a periwinkle/cornflower blue, a mint/spring green, white, and a red-orange/coral — plus a dim grey-violet for inactive lines; no gradients, no opacity, no fills except small solid dots/chips; all strokes appear ~1 px at native scale. — local files beside these notes.

### Inferences
- For a terminal recreation, popcorp's set (#4D9EFF / #00ED95 / #FFFFFF / #FF3A5D, grey #6F7173, black bg) is the closest thing to "canonical" because it was read out of the firmware SVGs by someone who patches them; the op1-design-kit set is a consistent, well-documented alternative. The screenshots' blue looks closer to the kit's #698EFF (more violet) than to #4D9EFF, which is consistent with OLED rendering/camera capture — treat ±hue drift as expected.
- "Orange" in TE's hardware vocabulary is rendered as a red-orange/coral on screen (#FF3A5D vs #FF423F); terminal implementers should pick a red-orange, not a yellow-orange.
- A fifth "dim" tone (#6F7173 grey or #625D77 grey-violet) is needed for grids, inactive ticks and decorative lines; dimming is done by darker colour variants, never alpha.

### Gaps
- No TE-published palette exists; exact `colors.svg` contents were not viewable (proprietary firmware; not mirrored anywhere public that I found).
- No Lospec / color-hex / Coolors / Figma Community / Dribbble palettes named OP-1 were found by search (Lospec search returned nothing relevant).
- The OP-1 field's on-screen palette may differ slightly (it is an LCD, not OLED); no field-specific hex values were found.

## Key Question 2: Which screens feature animated characters/figures and what do they look like/do?

### Takeaway
Officially documented figures: the **cow** in the CWO effect (signal path drawn through its four stomach compartments), **two keyboard players** (synth mode) or **two gorillas** (drum mode) in the Finger sequencer, the **boxer** in the Punch effect, the **tape reels** with light physics in Tape mode, the **tombola** (rotating container with bouncing notes), and the telephone exploded view in Phone. Other screens are diagrams (envelope curve, FM blocks, string model, Grid plate, Nitro road/gearstick, Spring radar, mixer gauges/ladders).

### Cited Findings
- CWO cow (official TE OS-update text, quoted by CDM): "We made the graphics for CWO to resemble a cow, digesting and processing the audio signal through it's four stomach compartments, producing a very unique result." The effect was inspired by Magnus Lidström's Echobode; it arrived in a 2013 OS update ("OP-1 OS update #13585"). — [CDM, 2023](https://cdm.link/2023/04/a-free-frequency-shifter-delay-with-a-cow-for-max-for-live-and-other-shifter-delays/)
- CWO reference type/params: "pitch shifting delay" with frequency, delay, feedback, sideband. — [teenage.engineering/guides/op-1/original/reference](https://teenage.engineering/guides/op-1/original/reference)
- op1repacker ships graphics mods that swap the CWO cow: `gfx-cwo-moose` ("Replaces the cow in the CWO effect with a moose"), `gfx-cwo-cat`, `gfx-cwo-dog`; also `gfx-tape-invert` (moves tracks to top of tape screen) and `gfx-iter-lab`. — [op1hacks/op1repacker README](https://github.com/op1hacks/op1repacker)
- Finger sequencer (official): "Two keyboard players appear in Synth mode, or two gorillas in Drum mode. Each white key is a pattern shown as checkered rows filled with white crosses. A green dot shows swing." The guide says finger works the same in both modes "(animations differ)". — [teenage.engineering/guides/op-1/original/sequencers](https://teenage.engineering/guides/op-1/original/sequencers)
- Metropolis review: the Finger sequencer in drum mode "conjures twin gorillas" resembling Donkey Kong whose movements are synced to keyboard taps. — [Metropolis Magazine](https://metropolismag.com/products/teenage-engineerings-new-synthesizer-is-class-one/)
- Tombola (official): notes are dropped into a rotating container; Orange = bounciness ("mass", harder hits play louder), Green = heaviness ("gravity"), White = opens the tombola to release notes, Blue = rotation speed/direction; SHIFT+Blue = crank mode. — [teenage.engineering/guides/op-1/original/sequencers](https://teenage.engineering/guides/op-1/original/sequencers)
- Open-source Tombola clone describing the shape: "a hollow hexagon that balls bounce around inside", each ball tied to a MIDI note triggered on wall hits. — [tjex/ofTombola-sequencer](https://github.com/tjex/ofTombola-sequencer)
- Pattern sequencer (official): a 16-step grid with a horizontal cursor line and a vertical cursor line that moves across in live mode. Sketch: freeform drawn shape controls pitch; SHIFT+White enables a visual grid; "Shaking the OP-1 erases the sketch." Endless: the guide page embeds an animated SVG for it. — [teenage.engineering/guides/op-1/original/sequencers](https://teenage.engineering/guides/op-1/original/sequencers)
- Tape reels (CDM 2010 hands-on): "A simple, iconic on-screen representation of a reel-to-reel shows you your recording in real-time, with even some light physics simulation so it behaves like tape when you stop the transport." All "in high-density, 60 fps glory". — [CDM 2010](https://cdm.link/2010/01/17/teenage-engineerings-op-1-instrument-hands-on-videos-why-its-different/)
- Tape screen (official): "Recorded material shows up as gray lines and is referred to as takes." An active track with recorded material shows orange lines; a take turns blue when centred under the tape head. With Beat Match on, "bar markers just above the tape tracks" appear (1 bar = 4 beats = 16 steps). Blue scrubs, White = tape speed, Orange = record level. — [teenage.engineering/guides/op-1/original/tape-mode](https://teenage.engineering/guides/op-1/original/tape-mode)
- Sound On Sound: at boot the unit shows "an image of reels and scrolling tape"; with beat matching, "bar lines scroll along with the tape"; the mixer screen shows "a graphic representation of the entire sound path"; FM parameters "move around on screen" as you adjust them. — [Sound On Sound](https://www.soundonsound.com/reviews/teenage-engineering-op1)
- Effect reference list (official): Delay "solid state delay" (size, speed, feedback, mix); Grid "three dimensional feedback plate" (X size, Y size, Z feedback, mix); Nitro "dual resonant turbo filter"; Phone "hacked telephone system" (tone, phonic, baud, telematic); Punch "hard hitting low pass filter" (frequency, punch, rounds, power); Spring "mathematic reverb" (tone, turns, damping, send). — [teenage.engineering/guides/op-1/original/reference](https://teenage.engineering/guides/op-1/original/reference)
- Drum sampler encoders (official): Blue pitch, Green in-point, White out-point, Orange play mode (play to end / loop / play once); SHIFT+Orange = level. DBox: Blue pitch, Green waveform, White envelope, Orange cross-modulation. — [teenage.engineering/guides/op-1/original/drum-mode](https://teenage.engineering/guides/op-1/original/drum-mode)
- Designboom's screenshot caption lists the OLED screens photographed: pulse engine, drum sampler, tape recording, master EQ, "special mastering effects (including 'the punch')", envelope graphs, mixer, an LFO modulator, record buttons. — [designboom](https://www.designboom.com/?p=15488)
- **Reference screenshot 1** (`reference_op1_screens.png`, 8 tiles): (a) a signal-flow/arrangement screen with blue "F" + three overlapping circles, green waveform/"H", white "T", red "M" icons across the top and white bar-shaped tape blocks on a dim grid below; (b) a sampler screen: "C2 ♩+10" in white, a green waveform over a blue dashed region with a small circled handle, red/white arrows top-right; (c) **Tape**: boxed white "4", timer "2:50:20", two thin-line reels with hubs, a tape path with a small square tape-head icon, four track lanes with tiny blue/orange ticks at the right edge, "FX" and bar markers at left; (d) **EQ**: red arrow to boxed chip "MAX EQ", three outlined solids (blue cylinder LOW, green prism MID, white cone HIGH), and a boxed "CLEAN" chip; (e) **Punch**: FREQ (blue) / PUNCH (violet-blue) / ROUNDS (green) 45 / POWER (red) 45, a line-art boxer in green with red gloves, boxed "FX" chip, small segmented ladder; (f) **Envelope**: a blue ADSR curve with dots at breakpoints and dashed verticals on a dim baseline; (g) **Mixer**: four needle gauges with tick arcs and small "L○R" pan markers, then huge numerals "02 34 45 23" in blue/green/white/red; (h) **LFO**: blue clock icon SPEED, green triangle AMOUNT "34", white DEST waveform box, red P.DEST dial; plus a hand/keyboard icon with "TO REC". — local file.
- **Reference screenshot 2** (`reference_op1_screens_2.png`, 6 tiles): (a) **CWO**: brown/orange line-art cow in profile with a blue needle gauge FREQ, green "DELAY 10", white "FDBACK 45", a boxed red "SIDEBAND" chip, and inside the cow a signal path: blue arrow → green ring → a dotted circle (stomach) → red coil (feedback) → red/blue striped circle; a vertical dim/red segmented ladder on the right and a green baseline with ticks; (b) **Nitro**: a first-person road in perspective made of green dashed lanes, a blue city skyline, FREQ gauges in blue (left) and red (right), a white "R" gear-knob, "FF" with gear numbers "4 5 6 7"; (c) **Spring**: blue concentric circles inside a violet square (radar/"R"), red horizontal input line, "INPUT" red, FDB 45 / SPEED 45 in white/green; (d) **Phone**: isometric exploded telephone handset in white/blue line art with green/red component dots, TONE gauge, PHONIC 45 green, BAUD 45 white, boxed red "TELEMATIC" chip, 45; (e) **Punch** (larger): green boxer, red gloves, FREQ/PUNCH violet-blue, ROUNDS green 45, POWER red 45, boxed violet "FX" chip, green segmented ladder; (f) **Grid**: isometric blue grid plate with a green box on it, X (blue) / Y (green) axes, a boxed "Z FDB" chip, red "MIX" with a red/violet segmented vertical ladder, "45". — local file.

### Inferences
- Animation vocabulary from the sources: reels spin with transport (and settle with "light physics" on stop), tape and bar lines scroll, mixer needles/numbers follow level, FM operator blocks move with parameters, Finger figures "play" on key taps, Tombola balls bounce under gravity/rotation, pattern cursor sweeps. Meter decay/peak-hold behaviour is not documented anywhere I found — treat it as an implementer's choice.
- Each screen uses exactly one big illustration (figure or diagram), four parameters laid out in encoder order (left→right, blue→green→white→orange/red), and huge numerals for the values.

### Gaps
- No written TE description of the Finger players'/gorillas' or boxer's exact animation frames; only video would show this. Reel spin rate, meter ballistics, and blink rates are undocumented.
- The "dancers"/"characters" sometimes mentioned in forums could not be tied to a specific official screen beyond Finger, CWO, and Punch.
- I could not access the original OP-1 Manual 1.2 PDF text (it extracted as images only) for the page-numbered illustrations the op1-design-kit cites (FM p.42, String/Digital p.41, DBox p.16, envelope p.12, mixer p.25, tempo p.27, Phone p.44). — [manual PDF](https://teenage.engineering/_img/54b7f9bf8681400300255cab_original.pdf)

## Key Question 3: Are there open-source OP-1 UI recreations, clones, emulators, editors, or design kits?

### Takeaway
Yes, but almost all are *custom-firmware* tooling for the real device rather than browser emulators: op1repacker (MIT), op1hacks/docs, op1svg, op1r / op1r-src (GPL-3+), Hundekraft "Kennel" op1-workshop SDK, SquareWave Studio's op1-design-kit (MIT, with Iosevka preview font and hex tokens) and op1-mods (GIN). Web/desktop recreations are thin: a CodePen with rotating reel images (liva_raita), Zizwar/op1Vanilla (Web Audio UI), and OTTO (C++ OP-1-inspired groovebox with colour-coded encoders). No Figma Community or Dribbble recreation was found.

### Cited Findings
- **op1repacker** (op1hacks): Python tool to `unpack`, `repack`, `analyze` and `modify` OP-1 firmware; mods include iter synth, filter FX, subtle-fx, and graphics mods gfx-iter-lab, gfx-tape-invert, gfx-cwo-moose/cat/dog; MIT licence; based on research in the op-forums custom-firmware thread; warns it can void warranty/brick. — [github.com/op1hacks/op1repacker](https://github.com/op1hacks/op1repacker)
- **op1hacks/docs**: firmware `.op1` file = 4-byte CRC32 + LZMA-compressed TAR; `content/display/` holds "the UI graphics as .svg files"; `content/kerntable.db` (font kerning), `op1.db`, `op1_factory.db`, `tape.db`; code in `OP1_vdk.ldr` is XTEA-encrypted; files: README.md, boot-menu.md, hardware.md, keys.md, lfo.md, svg.md. — [github.com/op1hacks/docs](https://github.com/op1hacks/docs)
- **op1hacks/docs svg.md** constraints: supported elements svg, rect, g, line, path, polyline, circle, polygon, ellipse (defs/clipPath/use unconfirmed); path `d` needs one coordinate pair per `L`; only `matrix` transforms work and not on groups; more than 4 decimals crashes the OP-1; "Use the default colors and line widths, and stay close to the original TE OP-1 look." — [svg.md](https://github.com/op1hacks/docs/blob/master/svg.md)
- **op1-fw-archive** (op1hacks): "An archive of (almost) all OP-1 firmware versions" (proprietary firmware; useful only for local unpacking). — [github.com/op1hacks/op1-fw-archive](https://github.com/op1hacks/op1-fw-archive)
- **op1svg**: Python CLI that "normalizes SVG files so that the OP-1 understands them" (removes unsupported tags/attributes, converts styles to attributes, caps decimals at 4); packaged for Fedora as python-op1svg with sources on Pagure. — [Fedora package page](https://packages.fedoraproject.org/pkgs/python-op1svg/op1svg) / [man page](https://manpath.be/f38/1/op1svg)
- **op1r** (pcppcp/"popcorp"): patch set for stock firmware R246 adding synths (supersaw, fmbell, granular, mixtur, arc, aether, brassophone, dddd), effects (tape echo, clouds, reverb, palme, "in a room", steve), sequencers (quad LFO, euclid, dots, grids, oracle, peal), with custom screens; screen art credited to DAN76 and nvmsocool; "the sequencer and synth screens use a stroke font by ultralazr, and svgfont.py is by Martin Mairinger"; encoders described as "blue, green, white, and red"; licence GPL-3.0-or-later with extra firmware-combination permission; third-party parts MIT. — [github.com/pcppcp/op1r/wiki](https://github.com/pcppcp/op1r/wiki)
- **op1r-src** harness scripts reference the real asset names: `op1_246/content/display/opfont.svg`, `mixer.svg` (`mixaux_preview.py` "reads op1_246/content/display/mixer.svg + opfont.svg"), `fxgeneric.svg` identical to stock `iter.svg`; `svgfont.py`: "Extract stroke polylines per glyph from the OP-1 opfont.svg"; `drumplus_preview.py` notes glyph row tops in opfont.svg at `(-142.4, -57.4, 27.6, 112.7, 197.7, 282.8)`; render harness uses "butt caps (as the OP-1 rasteriser)". — [github.com/pcppcp/op1r-src](https://github.com/pcppcp/op1r-src) (via GitHub code search)
- **op1-design-kit** (SquareWave Studio / Joseph "Instant_Fidelity" Holland): "Community design patterns, original screen examples and a portable skill for the original OP-1"; MIT for original code/guidance; manual images excluded; includes `op1-ui/tokens/op1-ui.json` (colours, type profiles, 8-unit grid, safe area 8/8/16/8, critical content above y=140), docs DESIGN.md, STOCK.md, FONTS.md, ICONS.md, GRAPHICS.md, a browser workbench that can load *your own* `opfont.svg` in-memory, and bundled Iosevka Thin/ExtraLight/Light/Regular (OFL) as the preview font. Published site: https://squarewave-studio.github.io/op1-design-kit/. — [github.com/squarewave-studio/op1-design-kit](https://github.com/squarewave-studio/op1-design-kit)
- op1-design-kit type profiles measured from stock SVG text templates (geometric heights in 320×160 units): browserRow 13.33 (presetbrowser.svg), parameterValue 20 (sampler.svg "gain"), tempoCompact 35.83 (tempo.svg "bpmS"), clockNumber 40.31 (clock.svg "hour"), tempoMedium 42.81 (tempo.svg "bpmM"), mixerLevel 53.34 (mixer.svg "lev1"); stroke widths 1.5 (2 for clock); "Original-device work uses a 400×198 output; a uniform 1.25 host scale yields 400×200"; native text constructor heights observed 12, 16, 18, 20. — [op1-ui.json](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/tokens/op1-ui.json) and [DESIGN.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/DESIGN.md)
- op1-design-kit STOCK.md screen families: engines (FM, String, DBOX) "give the engine a recognisable identity"; FM uses "enclosed values" inside blocks; String a "perspective model"; Mixer "four repeated lanes"; Tape "reel or recording identity … motion tied to musical progress"; the preset browser is two lists (Blue = type, Green = preset); the synth sampler has a compact overview region above a magnified waveform region. — [STOCK.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/STOCK.md)
- **op1-mods / GIN** (SquareWave Studio): an instrument built with the kit; cited for "playing versus editing hierarchy, encoder ownership". — [github.com/squarewave-studio/op1-mods](https://github.com/squarewave-studio/op1-mods/tree/main/mods/gin)
- **Hundekraft op1-workshop ("Kennel" SDK)**: plugin SDK for original OP-1; screen space 320×160; Q10 geometry helpers; artwork budget ~8 KiB, whole-file limit 512 KiB; supported SVG: groups, lines, circles, polylines, M/L/C/z paths, matrix transforms; no CSS/opacity/embedded fonts; screens declared with `screen: {"svg": ..., "symbol": "SCREEN_..."}`, `init(scr)` resolves nodes, `update(scr, dt)` runs on the GUI thread; optional `op1_screen_draw_cached` pixel cache. — [hundekraft.github.io/op1-workshop/llms.txt](https://hundekraft.github.io/op1-workshop/llms.txt)
- popcorp's runtime notes: show/hide/move/rotate SVG nodes by id (`op1_node_set_visible`, `op1_node_set_transform`, `op1_node_rotate`); draw raster lines after `op1_screen_draw()`; keep under ~150 lines/frame; tiny circles r≈1–2 don't render ("draw dots as two short crossing lines"); no `<text>`, no `stroke-dasharray`, no `rotate()`; use lowercase text IDs "because capitals and some upper-case letters are icons". — [popcorp #1373](https://op-forums.com/t/custom-firmware-on-the-op-1/4283/1373)
- maxaw's layout notes (post #1371): "147px usable height from the top of the screen", suggests an 8×8 grid on 320×160 and an "8 8 16 8 px margin as a safe zone". — [maxaw, op-forums #1371](https://op-forums.com/t/custom-firmware-on-the-op-1/4283/1371)
- **Maiko's custom firmware #250** (maikopruett.com/op-1): unofficial OP-1 firmware with a "tape-reel screen" for snapshot naming, an UNDO/REDO popup "modelled on the OP-1 field's", COM-screen storage bar; no hex/fonts published. — [maikopruett.com/op-1](https://maikopruett.com/op-1)
- **ultralazr/op1-oblique-strategies**: prior art for loading the OP-1 vector font locally (credited by op1r and the design kit). — [github.com/ultralazr/op1-oblique-strategies](https://github.com/ultralazr/op1-oblique-strategies)
- **OTTO** (bitfieldaudio): "An OP-1 inspired all-in-one synth/sequencer/sampler/recorder"; "Like the OP-1, the colours of the 4 rotaries corresponds to the colour of the option on screen that will be changed"; lead designer Tobias Pisani: "The only things that are really like the OP-1 are the graphics style and basic interaction model"; C++17, Faust DSP, Raspberry Pi target; ~2.8k stars; code uses `Colours::Blue/Green` and `colors::red, yellow, green, blue` for FM operators. — [Synthtopia](https://www.synthtopia.com/content/2019/03/01/otto-portable-groovebox-inspired-by-the-op-1-sneak-preview/), [github.com/bitfieldaudio/OTTO](https://github.com/bitfieldaudio/OTTO)

## Key Question 4: Did TE publish the OP-1 UI SVG assets? Is the firmware UI SVG-based, and what tools extract/patch them?

### Takeaway
TE has never published the screen assets, but the OP-1 firmware demonstrably *is* SVG-based: unpacking a `.op1` file yields `content/display/*.svg` (one file per screen), `opfont.svg` (the vector UI font), `colors.svg` (dynamic colours), and `kerntable.db`. op1repacker unpacks/repacks and patches graphics; op1svg sanitises SVGs for the device; op1r/Kennel load SVG screens by node id at runtime. All of this is for *your own* firmware copy; the assets remain TE's copyright.

### Cited Findings
- Firmware package format and layout: `.op1` = 4-byte CRC32 + LZMA → TAR with `content/display/` ("the UI graphics as .svg files"), `content/audio/…`, `kerntable.db`, `op1.db`, `op1_factory.db`, `tape.db`, `OP1_vdk.ldr` (XTEA-encrypted code), `te-boot.ldr`. — [op1hacks/docs](https://github.com/op1hacks/docs)
- Font file: "The OP-1 font is defined in the `opfont.svg` file. It defines the basic alphabet only in upper case and also contains additional UI symbols." Letters use lowercase ids (`a` = "A"), uppercase ids are UI symbols (`D` drum, `Q` sequencer, `X`/`H` FX, `A`/`E` envelope, `L`/`F` LFO, `S` synth, `T` tape, `M` mixer, `Y` keyboard, `I`/`J` blend, `Z` EQ), non-id characters hex-escaped (`_x3C_` = `<`), spacing from `kerntable.db`. — [op1hacks/docs README](https://github.com/op1hacks/docs)
- Design kit's inventory of the common stock font: "A–Z, 0–9 and punctuation `! " # % * + , - . / : ; < = > ? _`, plus uppercase icon IDs `D Q X A L H E F S T M Y I J Z` and non-character ID `_x34_by4`"; apostrophes, parentheses, degree signs, µ and accents are *not* present. — [op1-design-kit FONTS.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/FONTS.md)
- Where to get it legally: "download your own original OP-1 firmware from TE's official downloads (https://teenage.engineering/downloads/op-1)… follow op1repacker's setup and unpacking instructions… Keep the firmware, unpacked files and any derived font data in a private folder outside this public repository… do not download somebody else's extracted copy." — [op1-design-kit FONTS.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/FONTS.md)
- The kit's CI explicitly forbids committing `opfont.svg`, `kerntable.db`, `colors.svg`, `.op1`, `.ldr` etc. (`tools/check_public_assets.py` FORBIDDEN_NAMES). — [op1-design-kit repo](https://github.com/squarewave-studio/op1-design-kit) (via code search)
- SVG rendering limits on-device (community): only `matrix` transforms; >4 decimals crash; no opacity, CSS, `<text>`, dasharray, `rotate()`; one subpath per path; files of ~100 KB risk slow loads. — [op1hacks svg.md](https://github.com/op1hacks/docs/blob/master/svg.md), [popcorp #1373](https://op-forums.com/t/custom-firmware-on-the-op-1/4283/1373)
- The OLED hardware: iFixit lists the original OP-1 display as AMOLED, 320 × 160, 60 fps, 10,000:1 contrast. — [iFixit OP-1 device page](https://www.ifixit.com/Device/Teenage_Engineering_OP-1)
- Licensing status in the community: op1r's licence notes that "the Teenage Engineering firmware" is *not* covered by its GPL; the design kit says TE illustrations "retain their original copyright and are excluded from the MIT licence" and "MIT grants no rights to stock assets". — [op1r wiki](https://github.com/pcppcp/op1r/wiki), [op1-design-kit SOURCES.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/SOURCES.md)
- The OP-1 *field* guide says its display is "a custom made color lcd" (not OLED). — [OP-1 field user guide PDF](https://assets.teenage.engineering/_img/69f248938d433104c4dd1846_original.pdf)

### Inferences
- A terminal recreation should be built from *original* line-art in the same idiom (black bg, 1-px-ish strokes, four encoder colours, uppercase stroke lettering, big numerals) rather than from traced firmware SVGs, which would be derivative of TE's copyrighted art.
- The real pipeline (static SVG + named nodes toggled/transformed + a text service drawing `opfont.svg` glyphs) maps well to a terminal: static frame layer + a small "live" layer (needles, numerals, reels) redrawn on change.

### Gaps
- No public listing of every `content/display/*.svg` filename exists (op1hacks' docs mark "font and SVG usage details" as TODO). The names I could confirm from code are opfont.svg, colors.svg, mixer.svg, sampler.svg, presetbrowser.svg, tempo.svg, clock.svg, iter.svg, iter-lab.svg, fxgeneric.svg.
- The OP-1 field's display resolution was not found in any reliable source (one search tool guessed 128×64 from memory, which contradicts iFixit's 320×160 for the original and should be ignored).

## Key Question 5: What font does the OP-1 display use, and what are the closest free equivalents?

### Takeaway
The OP-1 screen font has no public name; it is a custom **monoline stroke (vector) font stored as `opfont.svg`**, uppercase-only, drawn with the same ~1.5-unit stroke as the artwork, with huge light-weight numerals for values. The best documented free stand-in is **Iosevka** (Thin/ExtraLight/Light/Regular, OFL), chosen by op1-design-kit; op1r uses a community "stroke font by ultralazr". Pixel fonts (Silkscreen, Pixel Operator, Departure Mono) are *not* a match for the OLED vector look, though they are fine for a character-cell terminal where everything is a bitmap anyway.

### Cited Findings
- "The OP-1 uses the characters in opfont.svg for drawing dynamic texts"; it "defines the basic alphabet only in upper case". — [op1hacks/docs](https://github.com/op1hacks/docs)
- "The vector UI font is part of the original OP-1 firmware… at `content/display/opfont.svg`… It is not a web font… The boot/console bitmap text uses a different font system." — [op1-design-kit FONTS.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/FONTS.md)
- Design kit preview font: "Use the bundled Iosevka placeholder for shareable host previews… Its weight follows the selected logical text size: XS 400, S 300, M/L 200 and XL/XXL 100"; bundled files Iosevka-Thin/ExtraLight/Light/Regular.woff2 under OFL 1.1; "Iosevka is not the OP-1 font and does not supply its stock icons." — [FONTS.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/FONTS.md), [SOURCES.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/SOURCES.md)
- Stock text sizes measured from firmware templates: 13.33 (browser rows), 20 (parameter values), 35.8/42.8 (BPM), 40.3 (clock), 53.3 (mixer level numerals), stroke 1.5 (2 for clock); native text constructor heights 12/16/18/20. — [op1-ui.json](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/tokens/op1-ui.json)
- Design-kit host spacing heuristic for the stock glyphs ("stock-local / optical-v1"): "minimum narrow-glyph advance of 0.22h, inter-letter gap of 0.17h and space advance of 0.48h" where h = cap height. — [FONTS.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/FONTS.md)
- op1r: "the sequencer and synth screens use a stroke font by ultralazr, and svgfont.py is by Martin Mairinger" (MIT). — [op1r wiki](https://github.com/pcppcp/op1r/wiki)
- Text rendering on device uses "butt caps (as the OP-1 rasteriser)". — [op1r-src render_mseq.py](https://github.com/pcppcp/op1r-src) (code search)
- Reference screenshots show the lettering: all-caps, monoline, slightly condensed, rounded-corner geometric letterforms (the "4" is open-topped, "5" has a flat top, "0" is a narrow oval), parameter labels ~XS size in the encoder colour, values 2–4× larger in the same colour; boxed "chips" (MAX EQ, CLEAN, SIDEBAND, TELEMATIC, FX, Z FDB) are small caps text in a 1-px rectangle. — `reference_op1_screens.png`, `reference_op1_screens_2.png` (local)
- The *printed* OP-1 field manual is typeset in Univers Next Pro Light (font dictionary embedded in the PDF: `/BaseFont /QEDJER+UniversNextPro-Light`) — this is TE's print typeface, not the screen font. — [OP-1 field user guide PDF](https://assets.teenage.engineering/_img/69f248938d433104c4dd1846_original.pdf)
- A third-party guide claims the TE wordmark is "custom-drawn brand lettering, not a released font" and that TE "uses monospaced type across products, packaging, web, and documentation" (uncited). — [madegooddesigns.com](https://madegooddesigns.com/?p=18854), [blakecrosley.com](https://blakecrosley.com/guides/design/teenage-engineering)
- Reddit font-ID threads surfaced only generic pixel suggestions (Departure Mono, Unifont) with no confirmed OP-1 match. — [search results summary; no authoritative thread found]

### Inferences
- For a character-cell terminal, the font is dictated by the user's terminal; the OP-1 "feel" comes from: uppercase everywhere, labels in the encoder colour, and *values rendered as large multi-cell block/figlet numerals* in the same colour (mimicking the 53-unit mixer digits). A thin "light" terminal font (Iosevka Thin/Light, JetBrains Mono Light, Berkeley Mono Thin) gets closest to the monoline stroke look.
- Avoid heavy pixel display faces; the OP-1 is anti-aliased vector art at 60 fps, not a 1-bit LCD (that look belongs to the Pocket Operators / EP-133 segment display).

### Gaps
- No public name or designer credit for the OP-1 screen font; TE has not released it. No TTF conversion of `opfont.svg` is publicly distributed (projects deliberately refuse to ship one).

## Key Question 6: Design principles from TE talks/interviews about the UI

### Takeaway
TE's own statements are sparse but consistent: colour is the link between knob and graphic; graphics are "iconic" metaphors (tape reels, a cow, a boxer) rather than menus; constraints are a feature ("limitations are OP-1's biggest feature"); and the colours are chosen "to keep things playful". Independent reviewers add that the screen "fits perfectly" and "uses colour and animation meaningfully". Most "design principle" articles online are third-party interpretation.

### Cited Findings
- Jesper Kouthoofd (via Wikipedia): "limitations are OP-1's biggest feature"; designers used hardware constraints to encourage creativity. — [Wikipedia: Teenage Engineering OP-1](https://en.wikipedia.org/wiki/Teenage_Engineering_OP-1)
- TE OP-1 field guide: "encoders in the color palette of blue, ochre, gray and orange to keep things playful". — [OP-1 field user guide PDF](https://assets.teenage.engineering/_img/69f248938d433104c4dd1846_original.pdf)
- TE OP-1 original guide: "A green graphical element or text hints that the green encoder will change its value or position." — [layout chapter](https://teenage.engineering/guides/op-1/original/layout)
- TE on CWO: "We made the graphics for CWO to resemble a cow, digesting and processing the audio signal through it's four stomach compartments". — [CDM quoting TE's 2013 OS-update post](https://cdm.link/2023/04/a-free-frequency-shifter-delay-with-a-cow-for-max-for-live-and-other-shifter-delays/)
- OP-1 team (2010 interview): goal was to "create a modern portable unit with a real and intutive UI"; "a fun and creative tool"; inspirations listed include DX7, JX3P, SH-101, Nintendo, LSDJ, Buchla, Fairlight MFX3, Animac, Electrolux, Vortex; team included Johan Kotlinski (LSDJ). — [bogdanraczynski.com interview](https://bogdanraczynski.com/interview-teenage-engineering-te-op1-team/)
- David Möllerstedt (co-founder): "all of the op-1 development and design was done in house at teenage engineering by the original core team." — [cited in search summary of a TE interview; original URL not retrieved]
- CDM (Peter Kirn), 2010: "the greatest accomplishment of the OP-1 is making a small screen seem integral to a hardware design, rather than a concession to practicality"; "The display itself seems like part of the hardware and the instrument, rather than being a menu system or a tacked-on indicator"; "physical interactions map to iconic, graphic feedback… 60 fps". — [CDM 2010](https://cdm.link/2010/01/17/teenage-engineerings-op-1-instrument-hands-on-videos-why-its-different/)
- Sound On Sound: the display is "pin-sharp, intelligently laid out and uses colour and animation meaningfully"; "colour is the natural link between on-screen objects and encoders". — [Sound On Sound](https://www.soundonsound.com/reviews/teenage-engineering-op1)
- Reviewers: "wordy parameters and complex menus are swapped for imaginative scenes and interactive imagery" (SoundTech); each engine "is represented by a different graphic on the display" (Perfect Circuit). — [soundtech.co.uk](https://www.soundtech.co.uk/musicians-blog/our-guide-to-the-teenage-engineering-op-1.html), [perfectcircuit.com](https://www.perfectcircuit.com/teenage-engineering-op-1.html)
- Third-party design essay (uncited claims, flagged): Kouthoofd quote "If it doesn't look good, it doesn't sound good"; "Each mode takes over the full screen, with no persistent navigation. Four parameters stay visible and map directly to the four knobs. Functions are at most two button presses away"; "Waveforms animate in real time, tape reels spin, and mixer levels bounce." — [blakecrosley.com](https://blakecrosley.com/guides/design/teenage-engineering)
- op1-design-kit's distilled lessons (community, from studying stock screens): "The original TE screens leave plenty of black space around fine outlines and readable values. Colour connects the controls to the drawing… Prefer an understandable metaphor and a few controls over a miniature desktop panel"; "Four Encoder Lanes: Blue, Green, White, Orange, in physical order"; "Stock screens use several treatments. FM and Mixer use encoder-coloured numeric values. Phone pairs a Green PHONIC label and an Orange/Red TELEMATIC label with White numeric values." — [DESIGN.md](https://github.com/squarewave-studio/op1-design-kit/blob/main/op1-ui/docs/DESIGN.md)
- OP-Z: "Gone is the OP-1's signature display, and once you do add another device, you can follow beautiful animated screens that give you feedback on what you're doing" (screens live in the companion app). — [CDM on OP-Z](https://cdm.link/teenage-engineering-has-an-op-z-prototype-and-its-awesome/)
- EP-133 K.O. II: "K.O.II has a custom display that features 66 unique icons", each marking a feature to aid navigation; a review calls it "what TE calls the 'world's first super segment hybrid display', reminiscent of colour-screen LCD games of yore". — [teenage.engineering/guides/ep-133/screen](https://teenage.engineering/guides/ep-133/screen), [Horizon/Everand review](https://www.everand.com/article/694130185/Horizon)
- Pocket Operators (ancestor of the EP-133 look) had "Game-and-Watch-style LCD displays". — [Yanko Design](https://www.yankodesign.com/2023/11/23/teenage-engineering-made-a-tricorder-like-gadget-thats-actually-a-portable-synthesizer/)

### Inferences
- Design rules an engineer can apply directly: (1) black background, one illustration per screen that *is* the metaphor; (2) exactly four parameters in fixed left→right encoder order, each label + value in its encoder colour; (3) values shown as huge numerals; (4) secondary state as small boxed chips (FX, CLEAN, MAX EQ); (5) needle gauges with tick arcs and vertical segmented ladders for continuous amounts; (6) dim grey for grids/inactive, never alpha; (7) motion only where it explains the mechanism (reels, balls, players, needles).
- The OP-1 field and EP-133 are different design languages (LCD with finer detail; segment/icon display) — for "OP-1 look" target the original's OLED vector style.

### Gaps
- No talk/interview specifically about the OP-1 *screen graphics* design process, nor a credit for the illustrator/animator, was found (Bark & Bite did external CGI marketing animation only, per a primarytech.com post).
- No TE statement about animation timing (reel speed, meter ballistics, blink rates).
